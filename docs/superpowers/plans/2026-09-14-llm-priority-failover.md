# 多 LLM 优先级与审计自动切换

## 概要

新增多套 LLM 配置及运行时优先级客户端。当前根配置启用两项：

```yaml
llm_priority: "01"
llm_list:
  - # 0号：当前 #main Pi 配置
  - # 1号：当前 #3.8 Agy 配置
```

Pi 在非最低优先级触发既有审计告警时，发送一次邮件和广播、切换到下一配置，并立即重试原请求；最低优先级仍按现有行为强制退出。最近一次审计后满 20 分钟，下一次请求恢复最高优先级配置。

## 配置与接口

- `Config` 新增 `llm_list: list[LLMConfig]` 和规范化后的 `llm_priority: str`；保留 `Config.llm` 作为最高优先级配置的兼容访问入口。
- 优先级字符是 `llm_list` 的零基索引；终端同样显示 `0号`、`1号`。例如 `"10"` 表示先用列表第 1 项，再用第 0 项。
- 省略 `llm_priority` 时按列表长度动态生成：一项为 `"0"`、两项为 `"01"`、三项为 `"012"`。
- 限制列表为 1 至 10 项；显式优先级必须是带引号的字符串，并且完整、不重复、无越界地覆盖所有列表索引。
- 继续接受旧的单个 `llm:`，运行时转换为一项列表和优先级 `"0"`；同时配置 `llm` 与 `llm_list` 时给出明确错误。
- 根 `config.yaml` 将现有 `#main` Pi 块迁移为 0 号、现有 `#3.8` Agy 块迁移为 1 号，并修复后者当前被误归入 `language` 的缩进。
- 内置默认模板保留一个可直接使用的 DeepSeek 配置和动态优先级 `"0"`，同时提供注释化的多项示例；中英文配置文档展示三项时的 `"012"` 示例及旧格式兼容说明。
- 配置指纹纳入完整 `llm_list` 和优先级顺序，并继续脱敏所有端点、环境变量名和 CLI 路径信息。

## 运行时行为

- 在 LLM 层新增线程安全的优先级客户端，复用每项配置现有的 provider/tier 路由，不把切换逻辑放入 Orchestrator 或具体业务阶段。
- 启动时构造并校验优先级中的全部配置；任一备用配置缺少凭据、模型或 CLI 时立即报配置错误。
- 只有当前 Pi provider 已有的审计识别规则可以触发切换；普通异常以及其他 provider 的错误不触发降级。
- Pi 审计异常改为不可被 provider 重试的类型化信号。直接使用单个 Pi 客户端时仍发送通知并硬退出，避免改变旧行为。
- 非最低优先级审计时先原子推进一级；通知失败或 15 秒通知期限耗尽也不阻止切换。触发审计的请求随后在新配置上完整重放。
- 同一旧配置的并发审计只产生一次邮件、一次广播和一次降级；其他同时失败的请求观察到新配置后直接重试，不能连续跳过多个优先级。
- 审计后的恢复期限使用单调时钟记录。满 600 秒后，下一次新请求恢复到 `llm_priority` 的首项；不取消或迁移已经在执行的请求。
- 切换状态只属于当前进程，不写入 manifest；重新启动或断点续跑时从最高优先级开始。
- 聚合所有配置的 token 用量并保留现有 tier/provider 归因；事件账本增加审计降级和静默期恢复事件，记录来源编号、目标编号和原因。

## 终端与测试

- 请求状态事件增加 LLM 配置索引；Rich 进度栏始终显示 `LLM 配置：N号`，包括尚未发起请求、请求中、失败切换和恢复后的状态。
- 书籍流程与 SRT 轻量流程都绑定同一状态显示；SRT 仍保持独立工作流，只复用共享优先级客户端。
- 配置测试覆盖新旧格式、动态默认、重新排序、冲突格式，以及重复、缺失、越界、未加引号和超过十项等错误。
- LLM 测试覆盖立即重试、普通错误不切换、最低级硬退出、并发只降一级、通知失败仍切换、10 分钟边界及再次审计重置期限。
- 增加全部备用配置预检、事件转发、状态编号、JSON 诊断、跨配置用量聚合、配置指纹和 SRT CLI 显示回归测试。
- 验证运行相关定向测试、`test_architecture_boundaries.py`、`test_orchestrator_contract.py`、完整测试集、Ruff check/format check 和 `git diff --check`。
